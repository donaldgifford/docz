# Docusaurus Setup

Scaffolder details for `docz website init docusaurus`.

## What the skill runs

```bash
npx create-docusaurus@latest <site-name> classic --typescript
```

Then rewrites the generated files:

- `docusaurus.config.ts` — sets `title`, `url`, `baseUrl`,
  and points `docs.path` at `../docs/` (or wherever the
  repo's docs live).
- `sidebars.ts` — generates a sidebar from docz doc-type
  groups (adr/, rfc/, design/, impl/, plan/, investigation/).
- `src/pages/index.tsx` — homepage referencing repo
  README.

## `docusaurus.config.ts` deltas

```ts
import type { Config } from "@docusaurus/types";

const config: Config = {
  title: "{{ .SiteName }}",
  url: "{{ .SiteURL }}",
  baseUrl: "/",
  organizationName: "{{ .Org }}",
  projectName: "{{ .Repo }}",

  presets: [
    [
      "classic",
      {
        docs: {
          path: "../docs",
          routeBasePath: "/",
          sidebarPath: "./sidebars.ts",
          editUrl: "https://github.com/{{ .Org }}/{{ .Repo }}/edit/main/",
        },
        blog: false,
        theme: { customCss: "./src/css/custom.css" },
      },
    ],
  ],
};

export default config;
```

Key points:

- `path: "../docs"` — point at the repo's source tree
  instead of `./docs/`.
- `routeBasePath: "/"` — docs live at root rather than
  `/docs/`.
- `blog: false` — turn off unless explicitly requested
  (avoids stub content cluttering the site).

## Sidebar generation

`sidebars.ts` reflects docz's doc-type structure:

```ts
import type { SidebarsConfig } from "@docusaurus/plugin-content-docs";

const sidebars: SidebarsConfig = {
  docs: [
    "README",
    {
      type: "category",
      label: "Architecture Decisions",
      items: [{ type: "autogenerated", dirName: "adr" }],
    },
    {
      type: "category",
      label: "Design",
      items: [{ type: "autogenerated", dirName: "design" }],
    },
    // ... etc per doc type
  ],
};

export default sidebars;
```

The skill respects `.docz.yaml`'s `wiki.nav_titles` and
`wiki.exclude` here too, for consistency.

## Deploy workflow

`.github/workflows/website.yml`:

```yaml
name: Website

on:
  push:
    branches: [main]
    paths:
      - 'docs/**'
      - 'website/**'

permissions:
  contents: write
  pages: write
  id-token: write

jobs:
  build-and-deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          cache: 'npm'
          cache-dependency-path: website/package-lock.json
      - working-directory: website
        run: |
          npm ci
          npm run build
      - uses: actions/upload-pages-artifact@v3
        with:
          path: website/build
      - uses: actions/deploy-pages@v4
```

For Netlify / Cloudflare / S3 targets, swap the
upload-pages-artifact + deploy-pages steps for the
provider's action.

## MDX usage

After scaffolding, markdown files in `docs/` can embed
React components by switching to the `.mdx` extension:

```mdx
import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

# Configuration

<Tabs>
  <TabItem value="cli" label="CLI">
    `docz create adr "Use Postgres"`
  </TabItem>
  <TabItem value="api" label="API">
    `POST /api/docs { type: "adr", title: "..." }`
  </TabItem>
</Tabs>
```

## Versioning

Docusaurus's versioning command snapshots `docs/` into
`versioned_docs/<version>/`. The skill doesn't automate
this — versioning is a release-pipeline concern, not a
scaffold concern. Run `npm run docusaurus docs:version
<version>` manually when cutting a release.

## When to walk back to MkDocs

If after a month you're not using MDX, versioning, i18n,
or the blog, the Docusaurus overhead isn't paying off.
Run `docz website init mkdocs --force` to switch back and
delete the `website/` directory.
