# CLAUDE.md: `pkg/export/`

Loaded when a session works under this directory. The repository's map is the root `CLAUDE.md`. The docz-html plugin over
`pkg/export/html` is in `plugins/CLAUDE.md`, and the server's use of
`pkg/export/confluence` in `internal/export/CLAUDE.md`.

- `pkg/export/html/` — **public, semver-governed** standalone HTML page renderer and exporter (IMPL-0028 Phases 3–5, DESIGN-0025 §4–§7), a sibling of `pkg/export/confluence`. `Render(src, RenderOptions) (Page, error)` is pure: CR line endings are `ErrLineEndings`, no frontmatter `ErrNoFrontmatter` (both wrap the `document` sentinels), frontmatter lines are blanked so line numbers hold, and `kinds.ResolveRegions` over `RenderOptions.Spec` gives the regions (`Page.Inferred` when there were no markers). `outline.go` cuts the document into tabs: one per depth-0 region in order, the ToC dropped, each H2 outside a region its own tab, and an H2 with nothing under it, or text before the first H2, folded into the next tab. One goldmark parse per document (GFM + footnotes, a node renderer at priority 100, never `WithUnsafe`); top-level nodes go to a panel by their start line, headings shift down a level under the panel title with ids from `docparse.Headings` by line (a `uniqueSlug` copy of github-slugger for headings docparse cannot see), alerts become callouts, task lists read-only checkboxes, tables sit in `div.table-wrap`. Raw HTML is escaped except `br kbd sub sup span details summary`, rebuilt bare with every attribute dropped; an inline tag left open closes in its own paragraph, heading, or list text, and anything still open at the panel's end there. Links keep http, https, mailto, a `#slug` the page has, and `RenderOptions.Resolve`'s answer when it is a safe scheme; the rest are text in `Page.Links`. Images load only `https:` and `data:image/`. The skeleton is `templates/page.html.tmpl` through html/template, the theme and runtime between `<!-- docz:theme -->` markers as `template.CSS`/`template.JS`, rendered markdown through one `trusted()` helper; the eyebrow is `<Site> · <TypeLabel>`, and an empty panel reads "Not written yet.". The CSP is `default-src 'none'`, inline style and script, `img-src data: https:`, widened only by `MermaidCDN` to `cdn.jsdelivr.net` for mermaid 12.0.0 with SRI; `MermaidEmbed` inlines `mermaidScript()`, `assets/mermaid.min.js.gz` decompressed once by `sync.OnceValue` (1.6 MB in the binary; `just vendor-mermaid` gzips it from `ui/node_modules` at the version `ui/bun.lock` pins, and `TestVendoredMermaid` holds it to that version and to the CDN mode's SRI hash, so a lockfile bump without the recipe fails), and goldens cut the inlined copy to a placeholder as they cut the theme, and only a page with a diagram carries mermaid and `assets/mermaid-init.js` (theme tokens, `securityLevel: strict`, redraw on mode change). `Page.Hash` is `sha256:<hex>` of the body, which holds nothing time-dependent. Goldens under `testdata/golden/` cover every `.md` in the six type packages' corpora and the parity fixtures with the theme cut to its markers, plus `full-page.html` whole (`-update`); each parses with `golang.org/x/net/html`, which is a **test-only** import (IMPL-0028 question 7), as is each type package the goldens take a heading spec from. `FuzzRender` holds a page to one style, one script beside any widget islands (which must be JSON), and no `on*` attribute, `javascript:` URL, iframe, object, embed, form, or base. **Layout by region kind** (Phase 4): `layout.go` is DESIGN-0025 §4's table as data, `map[kind]row{Tab, Component}`; tabs appear in the order their first region does, and a kind the table lacks is a text tab named by its heading. `layout_test.go` pins every kind in `validate`'s catalogue and every embedded template to a row (or the `placedByParent` list) and each built-in template to its type's tab list. `components.go` dispatches a section through `sectionWriters` (component → writer); a writer that finds nothing it can lay out, or whose typed parse failed, falls back to the region as text, and a failed parse is one entry in `Page.Problems`, never a `Render` error. Typed facts come from `facts.go`, which parses `impl`, `runbook`, `adr`, and `investigation` **lazily, the first time a region kind they read is laid out, never by type name**, so a custom type carrying IMPL regions gets phase cards (`testdata/pages/custom-impl-regions.md`). Structure, state, and lines come from the typed facts; content comes from rendering the AST nodes at those lines through `markdown.spanTo` with a `replace` map. Phase progress counts as `impl.Doc.Progress` does (checked over every task but the skipped, so a deferred task counts in the total), pinned by `TestPhaseProgressMatchesImpl`; `docz inspect`'s task count is every checkbox, so the two differ when a task is skipped. `questions.go` is one `details.expand` per `kinds.OpenQuestions` question, options as `li.option`/`li.option recommended`, each `> **Resolved…**`/`> **Revised…**` paragraph a `p.resolution`, resolved closed and open `open`. **Widgets** (`widgets.go`): a `docz-flow`, `docz-stepper`, or `docz-scorecard` fence is decoded with yaml.v3 `KnownFields(true)` into its Go type (a scorecard result reads its own mapping, since `score: null` and an absent score decode alike), field-checked, and written as `figure.widget` with the JSON island (`json.Marshal` escapes `<`), the mount, and widgets.md's fallback; an invalid block is a `callout caution` naming each error at its document line, then the YAML, each error in `Page.Problems`. `pkg/export/confluence` folds the same fences into a collapsed expand titled Flow, Stepper, or Scorecard. `testdata/pages/` renders as a custom type with no heading spec: the IMPL-regions document, one per widget, one per widget error. **`Export(ctx, rp, ExportOptions) (Report, error)`** (Phase 5, `export.go`) is the repository run: `repo.List` (or `repo.Find` per id, in order), each type's spec from `kinds.SpecFromTemplate(repo.Template)` once per run, a page per document at its path below `docs_dir` with `.html` for `.md` (`pagePaths` accepts the **absolute** `DocsDir` cmd/ makes as well as a relative one), written through an `os.Root` on `Out` (`DefaultOut` `build/html` under the root), a page whose bytes on disk match reported `ActionUnchanged` and not rewritten, `DryRun` writing nothing and reading nothing from `Out`, a failed page `ActionFailed` with `Error` while the run continues, `ctx` checked between documents, and `PageResult.Body` (`json:"-"`) for a caller that prints the page. A run of more than one document adds `index.html` (`index.go`): markdown with one `<!--docz:listing:…-->` region per type (an unlisted kind, so a text tab named by its heading, and the page is not reported inferred), a table of id, title, status, and date in list order, rendered through `Render`. `resolve.go` is the run's `LinkResolver`: a relative link to a document the run exports becomes a relative link to its page (fragment kept), an image under the root of at most 1 MB a `data:` URL by extension, read through an `os.Root` on the root so nothing outside it is read, else `ExportOptions.Resolve`. `Hooks{PageDone}` ride the context by `WithHooks`/`HooksFrom` (`hooks.go`)
- `pkg/export/confluence/` — **public, semver-governed** Confluence Cloud export (IMPL-0023, DESIGN-0020), a sibling of `pkg/wiki` above the core. Three layers. **`Render(src, RenderOptions) (Rendered, error)`** is pure: a docz document through goldmark (GFM + footnotes, a `storage` node renderer at priority 100) to storage format — the H1 dropped, the ToC region blanked and replaced by the `toc` macro, alerts to panels, task lists to `ac:task-list`, tables `data-layout="full-width"`, mermaid fences to the Mermaid diagrams viewer's ADF extension plus a collapsed "Diagram source" expand (or a plain code macro under `MermaidCode`), relative links through a `LinkResolver` to `ac:link`/`ri:page` or a URL, and the unresolvable recorded in `Rendered.Links`. The output is checked well-formed (`MalformedError`), hashed (`sha256:…`) **before** the viewer macros' `local-id` placeholders (`00000000-0000-4000-8000-%012d`) are swapped for fresh UUIDs, so the hash is stable across runs while every save gets new ids. CR line endings are rejected; frontmatter lines are blanked rather than cut so line numbers survive. **`Client`** is the twelve-method surface Export needs (`SpaceID`, `SpaceHome`, `FindPage`, `Page`, `Body`, `CreatePage`, `UpdatePage`, `Folder`, `CreateFolder`, and `Property`/`SetProperty`/`Children` over a `Target{Type, ID}` naming a page or a folder, `Children` through `direct-children` returning `[]Node` of both kinds — IMPL-0024 Phase 3; a missing page, folder, or property is `(nil, nil)`; a create refused for its title is a `TitleError` naming the archived page that holds it, when one does; a nil `PageUpdate.Body` is a move that keeps the current body), and **`HTTPClient`** implements it over `net/http` **always through Atlassian's gateway** `api.atlassian.com/ex/confluence/<cloudId>`, the cloud id resolved once from the unauthenticated `<site>/_edge/tenant_info` and memoised with its error, because a scoped token works only there and an unscoped one works there too. A 429 honours `Retry-After` up to three retries (2s doubling without it), on a timer selected against ctx. Errors are typed — `AuthError` (401/403), `ConflictError`, `RequestError` (body capped at 512 bytes), `ConfigError` (wraps `ErrConfig`), and `PageError` (the first failed page, unwrapping to its cause) — and none carries the token. **`Export(ctx, rp, ExportOptions) (Report, error)`** plans the tree (parent → one page per type carrying its README index, titled by the wiki's nav-title precedence → its documents; the `api:` landing page as the parent's body and `additional_docs` under it when `api_pages` is on), reads **only through `ExportOptions.FS`** (`os.DirFS(rp.Root)` when nil; IMPL-0024 Phase 2 — documents listed with `fs.ReadDir` + `document.ParseFrontmatter` in `repo.List`'s order, ids resolved as `repo.Find` does, the plan pinned by `testdata/plan/*.golden.json` over a corpus repository through both `os.DirFS` and `fstest.MapFS`), resolves links against **everything a full export writes** before the caller's resolver, then reconciles each page per §3's flowchart in `decide()`: no page → create; no property → skip unless `Force`; a property not written by docz export (no id or version — the INV-0019 prototype's `{id, hash}`) → skip unless `Force`; version moved → skip "edited in Confluence (vN, expected vM)" unless `Force`; same hash and parent → `Unchanged`, no write; else update at version+1 with the message `docz sync <id> <hash prefix>`, then the `docz` property `{id, source, hash, version, docz}`. The **parent page stays where it is** (Confluence files a parentless page under the space homepage). ****Inline comments survive an update** (#158, DESIGN-0021 §4, IMPL-0024 Phase 5, `comments.go`): on `Updated` only, `Client.Body` reads the current page, `collectMarkers` reads its `ac:inline-comment-marker` elements by text content, and `carryMarkers` wraps each marker's text in the new render where it occurs exactly once inside one text node a reader sees (never under an `ac:` element outside the `anchorable` set, an `ri:` element, or in CDATA, and never splitting an entity or a rune), splicing bytes so stripping the markers gives back the render exactly (`FuzzCarryMarkers`); the rest land in `PageResult.Comments.Lost` and the CLI prints `WARNING: <id>: an inline comment on "<text>" lost its anchor`. The property keeps the render's hash, so a commented page never reads as changed, and adding a comment does not bump a page's version (tested live). **An API update never marks a comment dangling** (INV-0021, `TestLiveInlineCommentReattach`, 2026-10-16): a body written without the marker leaves the comment `open` and listed with no highlight, and a later body carrying the same `ac:ref` renders it anchored again, so restoring an anchor is a body write and nothing else. **Built on that (#184, DESIGN-0021 question 14)**: `collectMarkers` reads each marker as an `anchor` (ref, quote, up to 32 bytes of context either side within the paragraph, the heading above), the property carries `anchors` (every placed one as it now sits plus every lost one as it was), `carryMarkers` places a quote at its one occurrence or at the one whose context and heading score strictly best (a tie is lost), and `carryComments` merges the live markers with the remembered anchors, reports `Comments{Kept, Restored, Lost}`, and forgets a lost anchor whose comment the page no longer lists through the **optional** `CommentLister` (`InlineComments`, one request per update that lost something; `*HTTPClient` and `confluencetest` implement it, a `Client` without it forgets nothing). `comments_lost` on the API counts remembered ones too (spec 1.6.2). **Two layouts** (DESIGN-0021 §2, IMPL-0024 Phase 3): `layout: folder`, the default, puts a repository in a folder titled `sync.confluence.folder` else the last element of `ExportOptions.Repository` else the root's base name, found by `ExportOptions.Folder` (recorded id) or among the direct children of the `parent` page or the space homepage and created with a `{repo, docz}` property when missing — a folder with no property or another repository's is a `ConfigError` naming `sync.confluence.folder`, `Force` included — with every title but the home page's (key `docz:parent`, titled with the folder name) prefixed `<folder>: ` and orphans under `<folder>: Archive`; `layout: page` is Phase A's tree unchanged, which `plan_parity_test.go`'s fixture pins. Page properties carry `repo`, and a page whose `repo` names another repository is `Skipped` "belongs to <repo>" and never archived, whatever `Force` says; a Phase A property with no `repo` belongs to anyone. `ExportOptions.Pages` maps a property key to a recorded page id, looked up with `Client.Page` before the title so a renamed document is renamed in place, and the unchanged check compares the title too. `Overwrite` updates a page edited in Confluence (`PageResult.Edited{Version, Expected}` either way); `Force` implies it and alone adopts a page with no property. `RenderOptions.Overwrite` words the page banner "changes made here are overwritten by the next sync" instead of "kept until the next forced sync"; `buildPlan` sets it from `ExportOptions.Overwrite` **before** `Force` implies it, so a forced CLI run, a one-off, still says edits are kept. `PageResult` gains `Key` and `Hash`, `Report` gains `Folder *Node`. Orphans are archived only on a full run** (no `Types`, no `IDs`): a child of the parent or a type page carrying a valid property whose id is no longer exported moves under an `Archive` child, body untouched and the property's version brought along; a page whose title the run writes, or whose property is not docz export's, is never moved, and nothing is ever deleted. A failed page is reported and the run continues; ctx is checked between pages. `Export` prints nothing: **`Hooks{PageDone, Request}`** ride the context by `WithHooks`/`HooksFrom` in `repo`'s shape. goldmark is allowed for `pkg/export/` alone: `layer_test.go`'s `thirdPartyAllowList` maps each third-party module to the package prefix allowed it (yaml → `pkg/`, goldmark → `pkg/export/`), and the core may import nothing under `pkg/export/`. `confluencetest` (IMPL-0024) is the public in-memory site — a `Client` and, through `Handler`/`HTTPClient`, the v2 endpoints — used by docz-api's tests. `live_test.go` (`//go:build live`, `just export-live`, which sources `~/.config/docz/atlassian.env`) round trips a page and its property on a real site; nothing in `just test` or CI sets the tag. This repository enables the block for the scratch site (`.docz.yaml`, IMPL-0023 OQ 6), in the folder layout with no `parent` since IMPL-0024 Phase 4: a `docz` folder at the top of `DOCZ`. `docz export confluence` passes `owner/name` from the GitHub remote as `Repository` and prints a `WARNING:` line on stderr, whatever the log level, for each page skipped as edited in Confluence or as another repository's. **`impl` is opt-in** (ADR-0005, INV-0022): an empty `sync.confluence.types` is `Config.DefaultExportTypes()`, every enabled type except the built-ins whose registry entry carries `ExportOptIn` (only `impl`; a custom type has no entry so can never be dropped), in the CLI and on the server alike; a repository that wants IMPLs lists its types with `impl` in it, and `--type impl` or an IMPL id against a list that leaves it out is `NotExportedError` (exit 2), which also covers any type a non-empty list omits, where it used to export nothing silently.
