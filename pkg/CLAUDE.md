# CLAUDE.md: `pkg/`

Loaded when a session works under this directory. The repository's map is the root `CLAUDE.md`. The core is in
`pkg/doczcore/CLAUDE.md` and the exporters in `pkg/export/CLAUDE.md`.
The layer rules (`pkg/doczcore/layer_test.go`): the core never imports
a type package, nothing under `pkg/` imports `internal/`, and each
third-party module is allowed to one package prefix.

- `pkg/{rfc,adr,design,impl,investigation,runbook}/` — **public, semver-governed** typed readers, one package per built-in (IMPL-0018 Phase 1; DESIGN-0014 §2, ADR-0002). **Every built-in is a structured type, rigid by design**: a package per type rather than a generic `kinds`-only surface, because docz-api and docz-site want `doc.Phases[2].Tasks[0].Checked`, not a bag of regions; the escape hatch for everything else is the `api:` block's additional docs. Each package is the same four files — `doc.go` (the `Doc` struct and its lookups), `headings.go` (the `kind*` constants and the `var headings kinds.HeadingSpec` table, exported through `Headings()`), `parse.go` (`Parse(doc []byte) (Doc, error)`), `validate.go` (`Validate(doc []byte) []validate.Finding` and its `Code*` constants) — and the same contract: `Parse` never touches the filesystem and fails for exactly two things, no frontmatter and CR line endings. Everything else a document might be missing leaves its field zero for `validate.Document` to report against the schema, because a half-written proposal is the normal state of a proposal; `pkg/impl` is the one exception, with `ErrNoPhases`, since an IMPL with no phases has nothing of the type in it. `Parse` switches on the **region kind and never on the document's type name** (ADR-0002 R7), which is what lets a custom type carrying these regions parse with a built-in's package. Codes are `<type>.<family>.<rule>` — `rfc.{alternatives.empty,risks.no-mitigation,status.open-question}`, `adr.{decision.empty,consequences.empty,superseded.no-reference}`, `design.{goals.empty,status.open-question,decisions.mismatch}`, `impl.{phase.duplicate-token,phase.no-heading,phase.no-title,phase.no-tasks,task.empty,task.verify-no-command,task.skipped-no-note}`, `inv.{context.no-trigger,conclusion.no-answer,conclusion.verdict}`, and `runbook.*` (below) — plus exactly one `<type>.parse` finding for a document `Parse` rejected, since every other check reads a parsed `Doc`. A type package's production imports stop at L0 (`docparse`, `document`, `config`) plus `kinds` and `validate`; **the core never imports a type package** (DESIGN-0014 §6 R2, pinned by `TestLayerRules_*` in `pkg/doczcore/layer_test.go`), and nothing under `pkg/` imports the server's `internal/` (DESIGN-0016 §7). Each carries a golden corpus under `testdata/` of real fleet documents **snapshotted** as `.orig.md` (never read from `docs/` at test time) plus a generated marked `.md` sibling, with `.golden.txt` fact files (regenerate with `-update`), a `FuzzParse`, and the invariant that inference over the `.orig.md` yields the same facts as its marked sibling in every field but `Inferred` and the line numbers the marker lines shift; each `testdata/README.md` records what the corpus taught us
- `pkg/runbook/` — the sixth type package (IMPL-0022, DESIGN-0019 §4), the same four files plus `walk.go`, following `pkg/impl`. Its one grammar is the **step**: an ordered list item in a `steps` or `rollback` region (`docparse.ListItems`, `Ordered: true`). The walker is one pass with a stack of open steps — an ordered item closes every open step at its indent or deeper; ordered items indented under it are `Children` to any depth; continuation lines fold into `Text` (comments removed); a fenced block below a step is a `Command{Lang, Body, Line}` of the deepest open step whatever its indent; an `**Expected:**` line, folded across its own continuations, is `Expected`; a bullet under a step stays in its `Text`. Blank lines close nothing. **IDs are built from the heading's token, not its position**: `<token>.<n>[.<m>…]` for a procedure (`### Procedure 2B: Deploy`, and a tokenless `Procedure: X` takes its index), `S<index>.<n>` for a scenario, `<token>.R<n>` for a rollback; `Doc.Step(id)`, `Procedure(token)` (folded), and `Steps()` (depth-first) are the lookups. `Doc.LastVerified *Verification{Date, PR, Commit, VerifiedBy, Notes, Line}` is the Last Verified table's first data row, columns matched **by folded header name**, nil while every cell is empty; `VerifiedBy` splits on commas. Bold fields (`Service`, `Owner`, `Alert`, `Likely cause`, `Notes`) fold their wrapped continuation lines, which `kinds.Field` alone does not. `Parse` also fails for two procedures claiming one token (`*DuplicateProcedureError`). Sixteen codes: `runbook.parse`, `runbook.procedure.{duplicate-token,no-title,no-steps}`, `runbook.step.{empty,unordered}`, `runbook.scenario.{no-symptom,no-steps}`, `runbook.overview.no-owner`, `runbook.last-verified.{bad-date,bad-pr,bad-commit,no-verifier,extra-rows,missing}`, `runbook.status.no-procedure`. **No rule reads the clock**: a date's shape is checked, never its age. `step.empty` reads the item as written, so the template's `1. <!-- … -->` placeholder is not an empty step, and the rendered template has warnings only. `step.unordered` is silent for a region with no ordered item at all, which is the generic tier's `steps.not-ordered`. The corpus is docz's own RUNBOOK-0001/0002 with markers removed plus a hand-written `legacy-onboarding`, because no fleet of runbooks existed to snapshot

- `pkg/wiki/` — **public, semver-governed** MkDocs / Backstage TechDocs integration, promoted whole from `internal/wiki` (IMPL-0018 Phase 2, DESIGN-0014 §2.10). A **sibling** of the type packages rather than a member of `pkg/doczcore`, because it is an integration, not core and not a document type. `orchestrate.go` holds the two **operations** — the orchestration `cmd/wiki.go` used to compose inline, so a consumer gets the operation and not just the primitives. `Init(ctx, root, cfg, InitOptions) (InitReport, error)` writes `mkdocs.yml` (at `cfg.Wiki.MkDocsPath`) and the docs landing page (`<DocsDir>/index.md`, rendered from `doctemplate.ResolveWikiIndex`): each file is created when absent, `Skipped` when present, `Overwritten` when present and `InitOptions.Force` is set, and `InitReport{MkDocsPath, MkDocs, IndexPath, Index}` reports both paths plus an `Action` (`Created`/`Skipped`/`Overwritten`, with a `String()` so two consumers can't word the same run differently) for each — the paths are filled before any work, so a report returned alongside an error still says which files were at stake and a zero `Action` means that file was never reached. A file already present is **not** an error at this layer; refusing over a skipped `mkdocs.yml` is `docz wiki init`'s policy. `Init` deliberately does **not** touch the nav — `CreateMkDocs` leaves the `nav: - Home: index.md` placeholder and the caller calls `UpdateNav` next, which keeps the page count in `NavReport` instead of discarded. `UpdateNav(ctx, root, cfg, NavOptions) (NavReport, error)` rebuilds the `nav:` key from the documents under `cfg.DocsDir`, preserving every other key and the existing top-level section order (it reads `ExistingNavOrder` back out of the file even on a dry run, since that ordering is the one behaviour a user notices); `NavReport{Path, Entries, Pages, Written}` returns the `[]NavEntry` tree rather than rendered YAML, so the indented tree `docz wiki update --dry-run` prints is the *caller's* rendering. A missing `mkdocs.yml` surfaces as the read error wrapping `fs.ErrNotExist`; "run `docz wiki init` first" is cmd's wording. Both operations resolve config-relative paths under `root` via unexported `underRoot` (the same rule as `cmd.Runner.inRepo`, so neither calls `os.Getwd`) and check `ctx` between steps, returning the report so far with `ctx.Err()` and leaving already-written files written. Three things stay in `cmd/` on purpose: deriving the site name from the git remote (an L4 dependency, like the author name — `InitOptions.SiteName` arrives resolved, and the package's own fallback reaches no further than `filepath.Base(root)` then `"my-project"`), the `.docz.yaml` precondition, and all printing/logging. The **primitives** stay exported for a different composition: `CreateMkDocs(path, *MkDocsConfig)` builds the initial `mkdocs.yml` (cmd/ no longer constructs YAML strings inline), `ScanDocs`/`BuildNav`/`SortEntries`/`CountPages`, `ReadMkDocs`/`WriteMkDocs`/`NavToYAML`/`MergeNavOrder`, and `DirTitle`/`DocTitle`/`FilenameTitle`. `DocTitle` resolves a nav title as frontmatter `ID: Title` → `docparse.Title` → `FilenameTitle`; the local `firstH1` it used to call is gone (IMPL-0016 Phase 2), which made the H1 scan fence-aware, markdown-stripping, setext-capable, and no longer confused by a mid-document `---`
- `pkg/theme/` — **public, semver-governed** design for docz's HTML (IMPL-0028 Phase 1, DESIGN-0025 §3), stdlib only. A theme is **token values and nothing else**: `tokens/paper.css` (the default; light under `:root[data-theme="paper"]`, dark under `[data-mode="dark"]` and again under `prefers-color-scheme: dark` with no `data-mode`) `tokens/classic.css` (docz-site's dark look before DESIGN-0026, one block for every mode), and `tokens/charcoal.css` (a neutral dark, one block for every mode, 3px radii, and IBM Plex Sans / JetBrains Mono ahead of the system stacks in a separate `html[data-theme="charcoal"]` block, since fonts are not a token every theme must define). **`charcoal.css` is GENERATED and never hand-edited** (IMPL-0033 Phase 3, DESIGN-0028 §11): `just gen-charcoal` (root; it needs `just ui install`) runs `ui/scripts/gen-charcoal.ts`, which takes the dark set of `@donaldgifford/design-system`'s `tokens.json` at the version `ui/bun.lock` pins, converts oklch to hex, and writes the 58 names by `ui/src/theme/charcoal.ts`'s table (21 from the package, nine by rule, two accent tints, and docz's own 26 from the dark block of `ui/src/theme/docz-tokens.css`) into `ui/scripts/charcoal.template.css`, where the header prose and the font block are written by hand. Two checks hold it: `TestCharcoalMatchesPinnedDesignSystem` reads the version in the file's header against `ui/bun.lock` (the Go job has no `node_modules`, so it holds the version and not the bytes), and `just ui gen-charcoal-check` regenerates to a temporary file and diffs (the `ui` job, which has the package). **A bump of the package is the lockfile, `just gen-charcoal`, and `go test ./... -update` in one pull request**: the whole-page `full-page-charcoal.html` golden and the `export-html-*.json` contract fixtures' page hashes move with every colour (`test/parity` fails under `-update` because it defines no such flag; that is not a regression). `Names()` is `paper` then the rest by name, the order `ui/`'s generated list uses; `charts/docz`'s `site.config.theme` enum is pinned to it by `test/archive`, and `pkg/export/html` keeps one whole-page golden per theme. Both use `ui/`'s token names (`--color-bg-base`, `--color-fg-*`, `--color-st-*`, …) plus `--color-ok`, `--color-link`, `--color-warn`, `--color-bad`, `--color-on-accent`, `--color-code-bg`/`--color-code-fg` (code stays dark in every mode), and `--radius-card`/`--radius-control`. `base.css` holds the system font stacks an exported page needs and `ui/` never imports; `components.css` is the page's components and `runtime.js` its ES2020 runtime (one global `docz`: `mode`, `setMode`, `onMode`, `palette`, `showTab`; mode toggle as `docz:mode`, tabs as `docz:<id>:tab` from `<html data-doc>`, copy buttons, the IMPL task filter as `docz:<id>:filter`, in-page links that open their tab and expandables; without JavaScript every panel shows, stacked, because the runtime is what adds `html.js`). One `//go:embed` string per file; `CSS(name)` is `base + tokens + components` built once at package level, an unknown name (`""` included, no case folding) wrapping `ErrUnknownTheme` with the valid names; `Names()` returns a fresh slice. `theme_test.go` holds every theme to every token in every mode (and `ui/src/theme/contrast.test.ts` every text colour in every theme and mode to 4.5:1, which moved paper's failing colours in IMPL-0028 Phase 6), the two paper dark blocks equal, `components.css` and `runtime.js` to defined tokens and **no literal colour** (hex, colour functions, named colours) (`TestClassicMatchesUITokens` went with DESIGN-0026: docz-site's shell reads the design system's tokens, not classic's), and `TestCharcoalIsOneBlock` holds charcoal to one token block with no mode selector. The files are governed by name and token, not by byte

## Conventions in full

The root `CLAUDE.md` keeps a short form of these.

- Six built-in doc types: rfc, adr, design, impl, investigation, runbook. **`runbook` ships disabled** (DESIGN-0019, IMPL-0022): its block is in every generated `.docz.yaml` with `enabled: false`, it is absent from `EnabledTypes()` until a repo flips the flag, `repo.Init` skips it, and `docz create runbook` on a default config fails naming `types.runbook.enabled`. A short `runbook: {enabled: true}` block inside a `types:` block is filled from the registry. `plan` was a sixth through v1 and was removed on the v2 line (ADR-0003, IMPL-0018 Phase 4); a repo that keeps its `types.plan` block gets a **custom** type, so everything keeps working, and `docz create plan` renders the generic template with a stderr note (IMPL-0025 Phase 5)
- Type aliases: `implementation` -> `impl`, `inv` -> `investigation`, `rb` -> `runbook`. docz-api stores a built-in's registry aliases on its `doc_types` row (`internal/ingest/mapper.go` `typeAliases`), because the API resolves `{type}` from the row alone
- Templates must have `<!-- markdownlint-disable-file MD025 MD041 -->` after frontmatter; the IMPL and runbook templates carry `MD024 MD025 MD041`, because they repeat a heading per phase or procedure (IMPL-0025). A disable, never a `markdownlint-configure-file` object or a `markdownlint-enable`: both of those switch on a rule the repository turned off (checked against markdownlint 0.41). Every embedded template line fits MD013's 80 outside tables and fences, pinned by `TestEmbeddedTemplatesFitMD013`
- Lint: `golangci-lint` with `golines` for line length
- Tests: `t.TempDir()` for filesystem tests, golden files under `testdata/golden/`. `pkg/*` tests run in parallel (`t.Parallel()` on every top-level test and subtest); cmd/ tests stay serial because of the package-level `runner` and flag globals. cmd/ tests no longer use `os.Pipe` for output capture or `os.Chdir` for cwd manipulation — they construct a `Runner` with `Out: &bytes.Buffer{}` (or `io.Discard`) and `RepoRoot: t.TempDir()`, and set `repoRoot = dir` when going through `rootCmd.Execute()` so PersistentPreRunE picks up the test dir without process-level cwd changes
- Golden files are regenerated with `go test ./... -update`, never hand-edited
- The module path is `github.com/donaldgifford/docz/v2` (ADR-0002 Decision 3, IMPL-0018 Phase 0). Every in-repo import carries the `/v2` element; released v1.x tags keep the unversioned path, and a consumer pinned there is unaffected by the v2 line. `docz.just` derives the version-injection ldflags from `module_path`, because a `-X` naming a path no package has is ignored silently
