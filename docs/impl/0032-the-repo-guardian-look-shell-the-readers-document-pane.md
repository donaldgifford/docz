<!--docz:objective:start-->
## Objective

Give docz-site's chrome repo-guardian's look in light and dark, show each
docz document in the reader as the page `docz export html` writes, embedded
from a fragment the server renders, and colour each type's pages with its
type colour. The review page takes the same shell and the export's theme
for its document column.

**Implements:** [DESIGN-0026](../design/0026-docz-sites-shell-in-repo-guardians-look-and-the-readers.md)

<!--docz:objective:end-->

<!--docz:scope:start-->
## Scope

<!--docz:in-scope:start-->
### In Scope

- `RenderOptions.Fragment`, `docz export html --fragment`, and
  `docz.mount` in `pkg/theme/runtime.js`.
- docz-api's `.../docs/{doc_id}/html` endpoint, spec 1.8.0.
- `ui/src/theme/shell.css`, the fonts, and the shell's components
  restyled; the theme selector removed.
- `page.css`, generated by `ui/scripts/gen-themes.ts` through
  `ui/src/theme/scope-css.ts`.
- The reader's document route on the fragment, with a fallback to the
  React render, and `.docz-page` around the reader's other markdown.
- `--type-accent` and the `--color-t-*` values per mode and theme.
- The review page's shell and its document column's theme.

<!--docz:in-scope:end-->

<!--docz:out-of-scope:start-->
### Out of Scope

- The review page's tabs and components (IMPL-0031).
- A cache for rendered fragments.
- Any change to what an export lays out.

<!--docz:out-of-scope:end-->
<!--docz:scope:end-->

## Implementation Phases

Each phase builds on the previous one. A phase is complete when all its tasks
are checked off and its success criteria are met. The whole plan is one PR,
labelled `minor`.

---

<!--docz:phase:start-->
### Phase 1: The fragment and the mounted runtime

`pkg/export/html` can write a document without the page around it, and the
runtime can run inside an element.

<!--docz:tasks:start-->
#### Tasks

- [x] `RenderOptions.Fragment`: the `wrap` div inside
  `<div class="docz-page" data-theme data-doc>`, with no `<html>`,
  `<style>`, runtime, mermaid loader, or mode toggle. A second template,
  `templates/fragment.html.tmpl`, shares the body through a named
  template, so page and fragment cannot drift.
- [x] Every corpus document's fragment held equal to its page's body
  less the mode toggle (`TestFragmentsAreThePagesBody`), so the page
  goldens pin fragments too; one fragment golden whole; and
  `FuzzRenderFragment`, which allows no running script and no style.
- [x] `docz export html --fragment`, writing `.html` fragments, with the
  JSON report unchanged.
- [x] `runtime.js`: `docz.mount(root, {hash})`, every per-page lookup
  inside `root`, the tab memory keyed by `root`'s `data-doc`, `js` class
  on `root`; auto-start only when `<html>` has `data-doc`. The standalone
  pages' e2e (`export-html.spec.ts`) still passes unchanged.

<!--docz:tasks:end-->

<!--docz:criteria:start-->
#### Success Criteria

- A fragment parses with `golang.org/x/net/html` as a single element, and
  holds no `style`, no executable `script`, and no `on*` attribute.
- Exported pages and their goldens are byte-identical to before.

<!--docz:criteria:end-->
<!--docz:phase:end-->

<!--docz:phase:start-->
### Phase 2: The endpoint

docz-api serves each document's fragment.

<!--docz:tasks:start-->
#### Tasks

- [x] `GET /api/v1/repos/{owner}/{name}/types/{type}/docs/{doc_id}/html`
  in `api/openapi.yaml` (1.8.0) returning
  `{doc_id, html, hash, inferred, problems}`.
- [x] The handler: the type resolved as the document route does, the
  heading spec from the embedded template for a built-in and markers only
  otherwise, `Fragment: true`, `MermaidEmbed`, the theme from
  `config_snapshot`'s `html.theme`, and a link resolver to
  `/{owner}/{name}/{type}/{id}` for documents the repo holds and
  `/{owner}/{name}/pages/{path}` for its pages.
- [x] The OpenAPI contract test covers it; 404 for an unknown or
  disallowed document, as the document route.
- [x] `just ui gen-api` regenerates the client; an MSW handler serves a
  fragment for each demo document from
  `ui/src/mocks/__generated__/fragments.json`, which
  `TestUIFragmentFixtures` renders through the handler's own
  `renderFragment` (`-update`) and fails on when stale.

<!--docz:tasks:end-->

<!--docz:criteria:start-->
#### Success Criteria

- The contract test validates the route's request and response.
- A relative link to a sibling document in a fixture arrives as a site
  route.

<!--docz:criteria:end-->
<!--docz:phase:end-->

<!--docz:phase:start-->
### Phase 3: The shell and the scoped stylesheet

The site's chrome takes repo-guardian's look; the document theme moves
onto `.docz-page`.

<!--docz:tasks:start-->
#### Tasks

- [x] `ui/src/theme/shell.css`: repo-guardian's tokens mapped onto
  docz's names, light and dark, with the source noted at the top;
  `@fontsource/ibm-plex-sans` and `@fontsource/jetbrains-mono`.
- [x] `tokens.css`'s `@theme` takes the shell's dark set; `<html>` drops
  `data-theme`; `index.html`'s first paint sets only the mode.
- [x] Remove the theme selector and `docz:theme`; `DOCZ_THEME` names the
  document theme. Update `src/lib/theme.ts`, `appearance.ts`, the
  generated theme list's users, and the chart README.
- [x] `src/theme/scope-css.ts` and `src/theme/__generated__/page.css`,
  written by `gen-themes` and checked by `gen-themes-check` in
  `just ui ci`, and unit tests of the rewriter, including a shape it
  refuses.
- [x] Restyle the topbar, sidebar, directory, search, palette, menus,
  and badges to the shell's look.
- [x] `contrast.test.ts`: the shell in both modes; the document themes
  inside `.docz-page`.

<!--docz:tasks:end-->

<!--docz:criteria:start-->
#### Success Criteria

- The shell matches repo-guardian's look in light and dark.
- No rule in `page.css` matches an element outside `.docz-page`.

<!--docz:criteria:end-->
<!--docz:phase:end-->

<!--docz:phase:start-->
### Phase 4: The reader's document pane and the type accents

A document in the reader is its exported page.

<!--docz:tasks:start-->
#### Tasks

- [x] The document route fetches the fragment beside the document, puts
  it in the pane, calls `docz.mount(el, {hash: false})`, draws
  `pre.mermaid` with the site's mermaid, and routes clicks on site links
  in-app. The tab lives in `?tab=`.
- [x] Fallback to the React render when the fragment fails, with a quiet
  note.
- [x] The breadcrumb, metadata table, lifecycle, and view switch stay
  above the pane; "html" shows the fragment.
- [x] The reader's pages, index, and changelog render inside a
  `.docz-page`.
- [x] `--type-accent` on a type's routes from `typeColor()`; the eyebrow,
  breadcrumb leaf, active sidebar item, and repository mark read it, and
  the pane's `--color-accent` takes it. `--color-t-*` per shell mode and
  document theme, held to 4.5:1.
- [x] The XSS suite over a hostile fragment; axe over the reader.
- [x] e2e: tabs, the IMPL filter, a question, a widget, a diagram, an
  in-app link, and both modes.

<!--docz:tasks:end-->

<!--docz:criteria:start-->
#### Success Criteria

- A document reads in the reader as it does exported.
- `just ui ci` and `just ui e2e` pass; the bundle stays in budget.

<!--docz:criteria:end-->
