docz · component candidates

What docz-site draws by hand today that @donaldgifford/design-system 0.3.2 has no part for: a sidebar tree, an outline, a search result row, three palette slots, two top-bar controls, a vertical stepper, a disclosure, and a way to colour a badge by category. Colours, fonts and sizes are the package's tokens. The markup is hand-drawn, so this is a proposal. The companion page, mockup.html, shows docz-site with these and with what the package already has.

Already on its way

Four of boop's candidates are in the package's working tree, unreleased, and docz would use all four. They are drawn in the mockup as if released and are not proposed again here.

1. Sidebar tree new shell part

A repository's navigation: one row per document type with its count, each opening a list of that type's documents, and a pages tree nested as deep as the repository's folders. The package's SidebarMenuSub is one level and always open, and the package has no collapsible primitive. docz needs the caret to be its own button, because the row is a link to the type's page and the caret only peeks.

3. Search result row new props

The package's ListRow has a title, a subtitle, and leading and trailing slots. A search hit needs two more lines: a mono eyebrow over the title for the hit's coordinates, and a snippet under it with the matched words marked. The trailing time is a date over a time, where the package's Time writes one line.

4. Command palette slots new slots

The package's CommandDialog is an input over a list. docz's palette has three more regions: a row of filters under the input, a preview of the highlighted hit beside the list, and key hints along the foot. repo-guardian's palette uses none of them, so this is docz's shape, proposed as optional slots.

5. Top-bar controls new shell parts

TopBarLayout's end slot is documented as holding "search, clock, theme", and the package ships none of the three as a part. repo-guardian draws its Search button locally. docz needs two: the field-shaped button that opens the palette, and the light and dark switch.

Proposed: SearchTrigger (placeholder, shortcut, onClick, and the icon-only form below a breakpoint) and ModeToggle (mode, onToggle; it names the mode it switches to). The toggle is controlled, because where the mode is stored is the app's: docz shares one key with its exported pages (INV-0036 open question 2).

6. Vertical stepper new prop

A document's lifecycle: its type's statuses in order, with the document's own marked. The package's Stepper is horizontal and wraps, which reads well for three phases and badly for a type's statuses in a narrow column (an RFC has five, an IMPL five, and a custom type as many as it declares). Timeline is vertical but is a list of events with actors and times.

Proposed: orientation="vertical"

7. Disclosure new primitive

A panel that opens and closes under a labelled row. The package has no Collapsible or Accordion; Base UI has both. docz uses one for the lifecycle under a document's details, for the outline on a narrow screen, and it is what the sidebar tree (candidate 1) opens and closes with.

8. Categorical tone new prop and tokens

The package's Badge and Dot take a tone from a fixed list of states. docz colours by category: one colour per document type, on the sidebar's dots, the filter chips, and the active document's rail. The colours stay in docz, as the package's RFC says a mapping from an app's states does. What is missing is a way to hand one to a badge or a dot, and a small categorical palette for an app with no colours of its own.

9. Tokens two tokens, one decision

docz's shell has seven steps the package has no name for (INV-0036, Observation 4). Most map to a neighbour with no visible loss. Two do not, and one existing token behaves differently from docz's.

bg-base→ background
bg-raised→ card
bg-elevated, bg-hover→ muted, accent
bg-activeno neighbour: a pressed step
border-default, border-hairline→ border
border-strongno neighbour: a hovered edge
fg-primary, fg-secondary→ foreground
fg-tertiary, fg-muted→ muted-foreground

Proposed: --border-strong for a bordered control's hover and a popover's edge, and --surface-pressed for a pressed row; both go upstream (INV-0036 open question 4, resolved 2026-11-21). Everything else docz drops. The decision is the code surface: switch the toggle above and compare the two blocks in light. Either docz's site-rendered code moves to a Shiki theme pair that follows the page, or docz sets --code-bg itself and keeps it dark. Documents are not affected either way; a document's code is styled by its own theme.

Not a candidate, but the one name to watch: the package's --color-accent is a hover surface and docz's is the brand colour, primary in the package. A bg-accent left behind compiles and paints the wrong colour.
