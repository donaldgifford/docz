# CLAUDE.md: `cmd/`

Loaded when a session works under this directory. The repository's map is the root `CLAUDE.md`. The library `cmd/` drives is in
`pkg/doczcore/CLAUDE.md`, and the server's binary `cmd/docz-api` in
`internal/CLAUDE.md`.

- `cmd/` — Cobra commands (root, init, create, update, list, status, template, config, validate, inspect, wiki, version). **Every command orchestrates through `pkg/doczcore/repo` or `pkg/wiki`** (IMPL-0018 Phase 5, DESIGN-0014 §4): a handler resolves flags, makes one call, prints the report it gets back, and maps a typed error to an exit code. Nothing in `cmd/` walks a directory, renders a template, or splices a marker any more. `cmd.Runner` (runner.go) bundles the resolved Config with injectable dependencies (Out/Err writers, slog logger, time source, GitResolver, `RepoRoot`) **and a `Repo *repo.Repo`**; `repoOrOpen()` (list.go) returns it or builds `&repo.Repo{Root: r.RepoRoot, Cfg: &r.Cfg}` on the spot, which is what lets a test construct a Runner directly and still reach the operations. `cmdContext(cmd)` (runner.go) is `cmd.Context()` with a nil guard, because every RunE wrapper is also called as `runX(nil, args)` by a test and `(*cobra.Command)(nil).Context()` panics. `Execute()` wraps the root in `signal.NotifyContext(…, os.Interrupt)` so ctrl-C cancels mid-run; `repo` checks the context between per-type iterations and never mid-file, so what was written stays written. `loadAndValidateConfig` (root.go) resolves the repo root via `resolveRepoRoot()` — precedence `--repo-root` > `filepath.Dir(--config)` > `os.Getwd()` — then `repo.Open(ctx, root, cfgFile)`, applies `--docs-dir`, and calls `Cfg.Validate()` a **second** time: `Open` drops validation warnings by design (R4) and cmd is the layer that prints them. It then points `rp.Cfg` at `&r.Cfg` so there is one config object, not two that can drift. `(*Runner).hooks()` (hooks.go) maps `repo.Hooks` to slog debug lines and is installed with `cmd.SetContext(repo.WithHooks(…))`, which is how a library that prints nothing still narrates `--verbose`. Log-level resolution: explicit `--log-level` wins, else `--verbose`→debug, else info; invalid values fail at startup. Stable exit codes are signaled by wrapping the `errExitCode1`/`errExitCode2` marker sentinels in an `exitCodeError{msg, marker}`; `exitCodeFor` reads the marker with `errors.Is`. `status.go`'s `statusExitError` is the translation table from `repo`'s typed errors: `UnknownTypeError`/`TypeDisabledError`/`InvalidStatusError` → 2, `NotFoundError` → 1, `WriteError` unwrapped (line endings → 2, else 1). `docz validate` (validate.go, DESIGN-0015 §4) is the one command that composes all **three** validation tiers, because `repo` may not import a type package (R2) and ADR-0002 Decision 4 forbids a registry that would dispatch for it: `repo.Validate` returns the generic and repository findings, then `typeValidator(schema, typeName)` — an explicit five-arm switch, the only type-name switch in the repo — adds the per-type tier. Flags `--strict` (warnings and index drift fail too), `--format text|json`, `--fix` (`repo.InsertRegions`, then re-validate and exit on the **second** report; the first is never printed, since printing findings the next line has already repaired is the most confusing thing it could do). **One document** (IMPL-0027, DESIGN-0024 §4): an argument that is not a type name and is shaped like an id (has a `-`) or a path (a separator or `.md`) goes through `resolveDocument` (inspect.go: type name refused, then `repo.Find`, then the path) and `repo.ValidateDocument`; the report has that one entry, no template or index entry, and `--fix` calls `repo.InsertRegionsIn` with the one path. A bare word that is neither stays on the type path, so `docz validate nonsense` is still an unknown type (exit 2). `applyTypeTier` runs the per-type tier over `DocFindings.Content`, the bytes the generic tier judged, so no path re-reads a file. Both JSON outputs carry `schema_version` and each document `content_sha256`; `testdata/golden/validate/{before,fix-before}.json` were captured from the code before those fields existed and pin them as additive. `docz inspect <id|path> [--format text|json]` (inspect.go) composes `ValidateDocument`'s single read with `kinds.ResolveRegions` (the type's spec from `repo.Template`), `docparse.Headings`/`TaskItems`, and `kinds.OpenQuestions` shifted to document lines, into DTOs with json tags (no tag on a frozen struct); exit 2 for a type name or a path the repo does not own, 1 for no such document. `docz create --format json` prints one envelope (`createOutput`: id, type, path, title, `generic_template`, the type report as `update`, the nav rebuild as `nav`, both null when they did not run); the note stays on stderr and a failed creation or refresh prints no JSON. `cmd/cli_contract_test.go` runs every governed command over copies of the parity fixtures (`fixtureRunner` in inspect_test.go copies with `os.CopyFS`; the fixtures are never touched in place) and validates each output against the closed schema with `santhosh-tekuri/jsonschema/v6` (format assertions on); `testdata/cli-contract/v1/*.json`, captured with `-update`, plus a hand-written review record, are re-validated every run. `docz export confluence` (export.go, IMPL-0023) is one call to `confluence.Export` plus printing: credentials from `ATLASSIAN_EMAIL`/`ATLASSIAN_API_TOKEN` (missing is exit 2 before any request, except that `--dry-run --out` without them renders offline through an `offlineClient` with no pages), the client built through the package variable `newConfluenceClient` (the seam `cmd/export_test.go` swaps for a fake), unexported links resolved to GitHub blob URLs by `blobResolver` from `GitResolver.RemoteURL`/`DefaultBranch` — and only when the file exists under the root, since a blob URL to nothing is a 404 — and `exportExitError` mapping `ErrConfig`, `AuthError`, `NotFoundError`, and unknown/disabled types to 2 and everything else to 1. `GitResolver` gained `RemoteURL` (origin normalised to `https://github.com/<o>/<r>` from SSH or HTTPS, `""` otherwise) and `DefaultBranch` (origin's HEAD, else `main`); `realGit` carries the repo root as `Dir`. `(*Runner).exportHooks()` maps the package's hooks to debug lines. `docz export html` (`export_html.go`, IMPL-0028 Phase 5) is one call to `html.Export`: `--type`, `--out`, `--stdout` (a dry run that prints the one page; more than one is exit 2), `--theme` (checked against `theme.Names`), `--mermaid embed|cdn|source`, `--format text|json`, `--dry-run`; arguments through `exportIDs`, links outside the run through `blobResolver`'s URL, `Site` the remote's repository name else the root's base name. Exit 1 when a page failed, 2 through `exportHTMLExitError` for an unknown or disabled type or a missing document. The JSON report (`exportHTMLOutput`: `schema_version`, `out` relative to the root, `dry_run`, `pages`, `total`) is governed by `api/cli/export-html.schema.json`, and the contract test runs it over five parity fixtures and a dry run; `TestCLIJSONContractFixtures` matches a fixture to the longest schema name it opens with, since `export-html` holds a dash. **Routing through `repo` made every command respect `enabled`**, which `config.ValidateType` never did: `list` on a disabled type is an empty listing, `status set` and the three `template` subcommands error, and `update` keeps its silent no-op only because cmd resolves the token itself before calling. Two policies stay in cmd on purpose: `docz create` and `docz template show` print `note: <type> has no template; used the generic one. Run "docz template override <type>" to write one.` on **stderr** when a type fell back to the generic template (`genericTemplateNote`, template.go; tested in the new `cmd/generic_template_test.go`, the only cmd tests IMPL-0025 rewrote being the two in `legacy_plan_test.go` written to fail when this landed); `docz init` never overwrites `.docz.yaml` even under `--force` (the library enforces it in `initConfig`, pinned by a test), and `docz wiki init --force` spends the flag by removing `mkdocs.yml` and calling `wiki.Init` with Force **off**, so a hand-edited `docs/index.md` survives — and it removes it **only when it is a regular file** (`os.Lstat`, so a symlink is not followed), because `wiki.mkdocs_path` is a config key that `config.Validate` does *not* run through the repo-relative path rules: before the swap such a value reached `os.WriteFile` and a directory failed there, where unlinking first would delete it (Phase 5 review pass, pinned by `cmd/wiki_force_test.go`). Out-of-root *overwrite* is still reachable and is v1.2.2 behaviour; closing it means validating `wiki.mkdocs_path`, `DocsDir`, and each type's `Dir`, which is a new hard config error and not a permitted parity delta. `getRunner()` is the accessor for tests that bypass PersistentPreRunE — wiki/list tests reset `runner = nil` in their setup helper so the previous test's writer does not leak. **`cmd/*_test.go` is frozen through the swap** (ADR-0001 Decision 7): `git diff --stat <pre-swap> -- 'cmd/*_test.go'` prints nothing, and the only new file is `cmd/validate_test.go` for the new command — the tests are the acceptance criterion, so editing one to make the swap pass would remove the evidence that it did.

- `api/cli/` — the **CLI's JSON contract** (IMPL-0027, DESIGN-0024 §3): `inspect`, `validate` (a `oneOf` of the plain report and the `--fix` output), `create`, `list` (the bare array, the one output without `schema_version`), `review` (the record docz-review writes), and `export-html` (`docz export html --format json`, `SchemaVersionExportHTML`) as draft 2020-12 schemas with `additionalProperties: false` on every object, embedded by package `cli` (`Schema(name)`, `Names`, `SchemaVersion{Inspect,Validate,Create,Review}` = 1; imported as `clischema` in `cmd/`). `$id` is `https://github.com/donaldgifford/docz/schemas/cli/<name>/v<schema_version>` and immutable; an additive field bumps the file's `$version`, a removed, renamed, or retyped one bumps `schema_version` and keeps the old file. The package test pins the `$id`s, every object closed, and each `schema_version` const equal to its Go constant. The producer (the cmd contract test) validates against the closed schema; a consumer derives an open variant and ignores unknown fields.
